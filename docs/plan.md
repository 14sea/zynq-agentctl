> Form A were all built and verified on the EBAZ4205, and a later Phase-2 added the
> adaptive RO loop, board-side safety guard, and an MCP server. For the *current*

## Context (why this exists)

Next-stage goal: let an agent (Claude) control the hardware circuit state of the
EBAZ4205 (XC7Z010) — rewriting a PL truth table via live ICAP LUT-INIT surgery, no reset.

The user's key insight: **Form A already exists right now** — Claude Code on the host
(WSL) *is* the agent, `/dev/ebaz-uart` *is* the channel, and all the past NAND flashing /
loadb / ICAP surgery was already this ad-hoc loop. So this plan is not "stand up Form A",
it is to **converge that ad-hoc loop into a first-class, repeatable, feedback-driven
"perceive → decide → act → verify" loop**, with a stable agent↔board command surface.

Architectural decisions already settled:
- **Executor path = Linux `/dev/mem` + HWICAP** (ruling out A9 AMP / OpenAMP; also not via the NEORV32 soft-core path).
- **A first, then B**: A = agent runs on the host, board is the actuator (the body of this plan); B = agent moves on-board + UART-PPP networking (only a scaffold roadmap at the end of this plan, not implemented).
- **Independent project** `/home/test/zynq_agentctl`, **copying** the needed files from `zynq_xpart` / `xilinx`, **never modifying the source projects** (see [[feedback-independent-project-dir]]).

### Verified, reusable facts (from zynq_xpart T2.2)
- HWICAP@`0x41400000` (registers WF=+0x100, RF=+0x104, SZ=+0x108, CR=+0x10C, SR=+0x110, WFV=+0x114, RFO=+0x118; CR bit0=Write, SR bit0=DONE/bit2=EOS). `icap_clk` must be wired to FCLK0 (it is, in the design).
- AXI-GPIO input@`0x41200000`, bit0 = INIT[0] of the LUT6 under test (all 6 inputs tied to 0).
- The only missing piece to hand the config-engine MUX to ICAP: `devcfg.CTRL[PCAP_PR]`=bit27 @`0xF8007000` (`0x4c00e07f`→`0x4400e07f` hands it to ICAP; restore `0x4c00e07f` afterwards, the edit persists).
- Target frame: FAR=`0x00400d9a`, word 73, bit 15 (prjxray `bit_00400d9a_073_15`).
- The frame sequence is extracted from the **RAW .bit** FDRI stream by `hwicap-make-framewrite.py <A.bit> <B.bit> <FAR> <wofs=73> <out.bin>` (prjxray .bits cannot be used — missing ECC word50). Minimal sequence = sync/RCRC/IDCODE(0x03722093)/WCFG/FAR/FDRI(202w = frame + neighbour pad)/CRC=0/DESYNC, **no GRESTORE/GTS**.
- Board environment: glibc + busybox (`CONFIG_DEVMEM=y`) + `fpgautil`, **no Python**; cross-compiler `arm-linux-gcc` is at `xilinx/build/buildroot/output/host/bin/`.
- Buildroot Linux boots from NAND; `fpgautil -b <file>` A-route runtime PL reconfig is verified (~37 ms, state=operating).

### The one real unknown in this plan (verified live at P1)
The T2.2 live edit was done under **miner U-Boot (no driver)**. This plan does it under
a **Linux running the `xilinx-devcfg`/`fpga_manager` driver**, changing PCAP_PR and driving
HWICAP via `/dev/mem`. The new variable = whether the active devcfg driver conflicts with
our direct register pokes. The U-Boot path is kept as a known-good control baseline (to isolate the problem).

## P0 — create project + starting-point verification (pure reuse, no new logic)

1. `mkdir /home/test/zynq_agentctl` and subdirs; `git init`; `cp` files in per the table above.
2. Write `README.md` / `.gitignore` (mirror the .gitignore convention in [[reference-github-repo]]; at minimum ignore `board/*.bit`, `firmware/icaphw`, `__pycache__`).
3. Bring the board to a **Buildroot Linux shell** (not U-Boot): if in U-Boot, `reset`; log in with `root\r` (empty password, see the [[ebaz4205-bring-up]] login timing — don't send two `\r` in a row).
4. Push `lut_A.bit` to `/tmp/lut_A.bit` (`host/uart-push-b64.py`, ~3 min @115200).
5. `fpgautil -b /tmp/lut_A.bit` → confirm `cat /sys/class/fpga_manager/fpga0/state` = `operating`, dmesg clean.
6. `busybox devmem 0x41200000` → expect bit0 = **0** (lut_A, INIT[0]=0).
   * Acceptance: GPIO probe reads 0, proving the design is in place and the starting state is correct.

## P1 — write the board-side `/dev/mem` HWICAP executor (the core new engineering)

**`firmware/icaphw.c`** (mmap `/dev/mem`, porting the U-Boot mw/md logic of `hwicap-uart.py` to native memory access):
- mmap three pages: HWICAP `0x41400000`, GPIO `0x41200000`, DEVCFG `0xF8007000` (each `mmap` page-aligned, `O_RDWR|O_SYNC`).
- Subcommands:
  - `gpio` → print the value at `0x41200000` (perceive).
  - `regs` → print SR/WFV/CR/ASR/RFO (health check, expect SR=0x5, WFV=0x3f).
  - `pcap-pr <0|1>` → read-modify-write bit27 of `0xF8007000`.
  - `writeseq <file.bin>` → read a big-endian uint32 stream and write it into WF using the **WFV-vacancy chunking + CR.Write(0x1) + wait-for-CR-clear** algorithm from `hwicap-uart.py:wf_write()`.
  - `edit <file.bin>` → combined action: print gpio(before) → `pcap-pr 0` → `writeseq` → `pcap-pr 1` → print gpio(after).
- `Makefile`: `CC=…/output/host/bin/arm-linux-gcc`, `-O2 -static` (or dynamic, glibc is in the rootfs), output ~20 KB ELF.

**Generate the frame sequences** (host):
- `host/hwicap-make-framewrite.py board/lut_A.bit board/lut_B.bit 0x00400d9a 73 seq/seqAB.bin` (→ writes the B frame, INIT 0→1).
- Swap A/B and run again → `seq/seqBA.bin` (→ writes the A frame, INIT 1→0).

**Board-side verification (P1 main acceptance = resolves the one unknown)**:
1. Push `icaphw` + `seqAB.bin` + `seqBA.bin` to `/tmp/`.
2. `chmod +x /tmp/icaphw`; `/tmp/icaphw regs` → expect SR=0x5/WFV=0x3f (HWICAP healthy).
3. `/tmp/icaphw gpio` → 0.
4. `/tmp/icaphw edit /tmp/seqAB.bin` → before=0, after=**1** (**first live LUT edit under Linux, no reset**).
5. `/tmp/icaphw edit /tmp/seqBA.bin` → before=1, after=**0** (reversible).
   * **If the devcfg driver conflicts** (after unchanged / stuck at PCFG_INIT): fallback in order — (a) first `echo 0 > /sys/class/fpga_manager/fpga0/...` or unbind `xilinx-devcfg`, retry; (b) use the U-Boot path (`zynq_xpart/scripts/hwicap-uart.py`) to write the same `seqAB.bin` as an A/B control, confirming the failure comes only from the single "Linux driver" variable, then decide whether DTS-disabling devcfg is needed.
   * Acceptance: the Linux `/dev/mem` path runs bidirectional live edit. The `/dev/mem + HWICAP` path is nailed down.

## P2 — command surface + end-to-end loop (agent = me, on the host)

**`host/agentctl.py`** (thin wrapper that converges P1's board-side actions into idempotent commands, callable from any Claude session):
- `ensure-linux` → ensure the board is in a Linux shell (reset + log in if needed; UART via `/dev/ebaz-uart`).
- `setup` → push `lut_A.bit`/`icaphw`/`seq*.bin` (only if missing) + `fpgautil -b` + `regs` health check.
- `perceive` → return `icaphw gpio` (current LUT state).
- `act <state>` → send `edit seqAB.bin`/`seqBA.bin` per the target state.
- `verify` → compare `perceive` against the target, return ok/retry.
- Reuse `host/uart-poke.py`, `uart-push-b64.py`; output via `--quiet`, low-noise (see [[feedback-tool-output-noise]]; don't use "dump/extract bitstream" wording).

**Closed-loop demo** `docs/loop.md`: the agent runs a full **perceive → decide → act → verify** —
read probe → set target truth table → select/generate frame → `edit` → read back probe to confirm →
retry if mismatched. The first version just toggles INIT[0]∈{0,1} between two states, which is enough
to prove the loop; can later extend to more LUT bits.

## P3 — (optional) hardening & gating

- Bake `icaphw` + `lut_A.bit` into the rootfs (Buildroot post-build or mtd5) to avoid pushing 2 MB over UART each session (mind the [[ebaz4205-bring-up]] Buildroot incremental-rebuild trap: a newly enabled package needs `make <pkg>` first).
- Wire in the sha256 gate of `measured-load.py` (M5) to verify `lut_A.bit`/`seq*.bin` are trusted before `setup`.
- Turn it into an MCP tool / `/loop` autonomy (so a non-me session or an autonomous loop can drive it too).

## Form B scaffold (roadmap, not implemented in this plan)

Goal: the agent truly moves on-board (the user's original vision). The blocking dead-end =
**networking** (the Ethernet hardware is dead, PS USB is not broken out — see [[ebaz4205-bring-up]]).
Feasible routes:
1. **UART-PPP + host NAT**: `pppd` on the board (needs Buildroot `BR2_PACKAGE_PPPD`) over `/dev/ttyPS0`, host-side `pppd` + iptables MASQUERADE to forward traffic out. 115200 ≈ 11 KB/s, enough for the Anthropic API JSON (slow but works); the UART baud rate can be raised later.
2. **Lightweight on-board agent**: 256 MB DDR can't run the Node version of Claude Code → use a slimmed-down agent built on **Python + the anthropic SDK** (but the rootfs currently has no Python; needs `BR2_PACKAGE_PYTHON3` + `python-requests`/SDK, and the rootfs size against the 64 MB jffs2 ceiling needs checking). The agent calls P1's `icaphw` directly on-board (local `/dev/mem`, no UART middleman).
3. Risk points: DDR/rootfs capacity, PPP stability (CH340 brownout), SDK dependencies on ARMv7. Evaluate these in detail in a separate session after A is verified.

## Pitfalls not to repeat (carried over from both projects' memory)
- A failed `fpgautil -b <bad.bit>` wedges DEVCFG (Timeout PCFG_INIT), recoverable only by power-cycle; `lut_A.bit` is known-good + CRC-disabled, don't deliberately load a bad file.
- HWICAP `CR=0x4` (Abort) wedges the write path, don't use it.
- Recovery anchor: openocd SLCR soft-reset (`mww phys 0xF8000008 0xDF0D; mww phys 0xF8000200 1`) + hammering `'d'` on UART → miner U-Boot.
- Use Opus throughout hardware operations, **never downgrade to Sonnet**; batch the commands the user must run by hand at the end of the response (see [[feedback-sudo-workflow]], [[feedback-tool-output-noise]]).
- Commit policy: local commits without asking, **always ask before push** (see [[feedback-commit-push-policy]]).
